# Запуск

Открыть проект в Unity 6, открыть сцену Game и запустить Play Mode. Проект разработан на версии 6000.6.6f1.

# Что реализовано

Реализована основная часть ТЗ: пошаговый бой двух отрядов, очередь ходов по Speed, ближняя и дальняя атаки с учётом позиции, лечение, пропуск хода и простой AI противника. Следующий ход начинается после завершения действия и его анимаций. Погибшие исключаются из очереди, бой заканчивается победой или поражением.

Дополнительно реализованы обе итерации со звёздочками. Есть пауза и продолжение по клавише Escape или кнопке Resume, перезапуск боя и выход из него с отменой текущего действия. Кнопка Escape слева вверху — выход из боя, Restart — перезапуск. Характеристики персонажей, параметры и наборы способностей, составы отрядов настраиваются через ScriptableObject. Есть одиночное и командное лечение, персонажам можно назначать сочетания разных способностей. При рестарте восстанавливаются исходные составы отрядов и очередность по конфигам персонажей.

# Основные технические решения

Использовал ручной DI через Init/Prepare, чтобы явно видеть зависимости и порядок инициализации. Обязанности разделены между менеджерами боя, хода персонажа, персонажей, способностей и интерфейса. FightManager управляет фазами боя через enum, CharacterTurnManager — отдельным ходом, а скиллы описывают последовательность применения способности. Такое разделение оказалось для меня удобнее при чтении и переработке проекта.

Взаимодействие между частями проекта построено на событиях и callbacks: они используются для выбора персонажей и способностей, завершения действий и передачи хода. В скиллах корутины и WaitUntil связывают эти сигналы в последовательность. Animation Events сообщают о моменте применения действия и завершении анимации, поэтому не требуется вычислять длительности клипов для ожидания. Переходами анимаций управляет Animator, для части визуальных эффектов используется DOTween. Настройки персонажей, способностей и команд вынесены в ScriptableObject отдельно от текущего состояния боя.

# Что осталось улучшить

В скиллах повторяется логика выбора цели и ожидания завершения действий. При добавлении новых способностей её придётся повторять, поэтому в дальнейшем хочу выделить общие части и упростить расширение системы. AI пока случайно выбирает доступную способность и подходящую цель, без оценки полезности действия.

После тестового планирую продолжить работу над инфраструктурой: подробнее изучить и внедрить UniTask для асинхронных последовательностей, Zenject — для управления зависимостями вместо ручного DI. Также хочу пересмотреть распределение ответственности и доработать места, которые сейчас сложнее читать, расширять и сопровождать.

# Время работы

Ориентировочно 8–9 дней активной работы, более 50 часов. Точный учёт часов не вёлся. Значительная часть времени ушла на изучение вариантов реализации, проверку и переработку архитектуры под собственное понимание проекта. AI использовался для помощи с кодом, обсуждения решений и проверок; реализация затем проверялась и перерабатывалась мной.
